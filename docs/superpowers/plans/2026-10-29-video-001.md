# Video 001, Script Stage: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Video 001 ("one neuron draws a line") taken through the bible's process up to and including Nate's interview: its ideas pressure-tested, its games and their memory addresses researched and verified, gameplay recorded, its experiments run, and its script written, cited, reviewed by the council and two adversarial reviewers, and put to Nate as an interview. No animation.

**Architecture:** Greenstone (Rust) gains a recorder that plays a game with a simulated player and writes each frame's 2KB of RAM and the buttons pressed, plus an optional footage take. A Python lab (`tools/series/lab/`, numpy, in the series venv) loads those recordings, trains and inspects the perceptron, and writes the numbers the script quotes into the video's `numbers.json`. The script loader fills `{name}` placeholders in a line's text from `numbers.json` and refuses unknown names, so every number in the script comes from an experiment.

**Tech Stack:** Rust (Greenstone, `src/nes/gym/`), Python 3.12 + numpy (series venv), the existing `tools/series` pipeline; web research for RAM maps and citations.

**Spec:** `docs/superpowers/specs/2026-10-29-interpretability-series-design.md`; the per-video rules and process are in `docs/series/bible.md`, and the sources in `docs/series/sources.md`.

- "Every line and fragment of every script is supported by a citation" — or demonstrated by a reproducible experiment (cited), or marked `framing`.
- "The script stands on its own": a blind listener, a cross-examiner or an interviewer could follow it without the video.
- "One narrow idea per video"; "no warm-up video"; "never: LLM clichés; 'we'll see why later'; anything unsupported, incorrect or uncited."
- Code shown on screen is the lab's working Python, stripped of what's irrelevant, type hints kept.
- Every RAM address used is cited to a published RAM map *and* verified in Greenstone by a test.
- Rust tests: `cargo test --release <filter>`; Python tests: `cd tools && series/.venv/bin/python -m unittest discover -s series/tests -t .`
- Training and heavy runs are small here (minutes on this machine); anything larger goes to velaryon via k8s, never the Pis.

## Review Focus

- A RAM address that means something different in another version of the ROM (e.g. a Japanese release): each address test names the ROM it was verified on (by SHA-1), and fails loudly on a different file.
- A perceptron that scores well because its inputs leak the label (the "cheating byte" belongs in 002, not 001): 001's experiments assert their inputs exclude the answer-key byte.
- A number in the script that no experiment produced, or that changed after a re-run: placeholders are filled from `numbers.json` at load time, so a missing or stale name fails the build.
- A recording whose simulated player never does the thing the question is about (Mario never jumps): the recorder reports how often the label is true, and the lab refuses datasets where either class is under 5%.
- The council or reviewers finding nothing because they weren't given the sources: each review is handed the script, citations, numbers, bible and sources file.
